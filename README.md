# Logi Local

**English** | [日本語](README.ja.md)

A Windows settings app for the **G703 LIGHTSPEED HERO**, using its USB receiver
or a wired USB connection. Mouse control runs locally without G HUB executables,
services, or SDKs. The implementation is based on observed HID++ 4.2 communication
and onboard profile format 4.

The React/Electron interface includes a Pi chat sidebar. Only the Python mouse
service stays resident when you close the settings window.

## Install

Requirements: Windows, Python 3.13, and Node.js 22.19 or newer.
This repository publishes source code, not a prebuilt Electron installer.

From the checkout, run:

```powershell
.\Setup-Desktop.ps1
.\Install-LogiLocal.ps1
```

Before installing or upgrading, exit any existing Logi Local instance from its
notification-area menu. The per-user installer:

- Installs to `%LOCALAPPDATA%\Programs\LogiLocal` without administrator privileges.
- Creates desktop and Start menu shortcuts.
- Migrates settings, cached firmware, and backups on first installation.
- Preserves the installation's settings on subsequent installations.
- Registers only the mouse service to start at login.

The installation uses your existing Python runtime. Open **Logi Local** from the
shortcut to configure the mouse. To run from the checkout instead, use
`Start-LogiLocal.vbs` after `Setup-Desktop.ps1`.

The optional `LogiLocal.exe` generated by `build.ps1` is the legacy Tkinter app,
not the Electron interface. Do not run both control implementations simultaneously.

## Everyday use

1. Exit G HUB. The settings app also provides a G HUB stop action under
   `本体と設定` (Device and settings). Local control refuses to start while
   conflicting G HUB processes are running.
2. Select a profile, edit DPI, polling rate, and button assignments, then choose
   `保存して反映` (Save and apply). This enables local control and verifies the
   active profile's DPI and rate by reading them back from the device.
3. For app-specific profiles, enter executable names or full paths, separated by
   commas. A profile with no target apps is the default. The first matching
   profile takes precedence.
4. Use `この設定を固定` to force a profile, or `アプリに合わせて切り替え`
   to follow the foreground app. Saving another profile reports which profile
   and DPI are currently active.
5. Close the window to exit Electron and Pi. The Python service keeps macros and
   app switching running. Reopen settings from the tray or shortcut; use
   `マウス制御を終了` in the tray to stop control and return to onboard settings.

Unsaved settings prompt before closing. Chat history is held in memory and resets
when the GUI exits. You can change automatic startup in the settings app.
If G HUB still starts at login, disable its entry in Windows Startup Apps.

## Features

| Feature | Local control running | Without the service |
|---|---|---|
| DPI and DPI stages | Supported | Save to onboard memory |
| 125 / 250 / 500 / 1000 Hz | Supported | Save to onboard memory |
| Six mouse/key button assignments | Supported | Save supported bindings onboard |
| Modifiers and shortcuts | Supported | Modifiers plus one regular key |
| Foreground-app profile switching | Supported | Unavailable |
| Macros: once, while held, toggle | Supported | Onboard macros not implemented |
| Battery and charging display | Voltage-based estimate | GUI needed for display |

Ordinary clicks come directly from the mouse. Only software-handled bindings use
HID++ feature `0x8110`. The app uses no global keyboard/mouse hooks and does not
intercept other input devices.

## Pi assistant

The right sidebar supports provider/model selection and streamed responses. Pi
uses existing `~/.pi/agent/auth.json` and `models.json`, or the directory specified
by `PI_CODING_AGENT_DIR`. Credentials are not passed to the React renderer.
Authenticate with Pi first, then refresh the sidebar. Local models registered in
Pi's `models.json` also appear in the list. Refresh reloads local authentication
and model configuration; it does not fetch a live provider model catalog.

Consultation produces a proposal. An explicit request to change or apply settings
allows Pi to save and apply scoped DPI, rate, button, profile, and macro changes.
Pi can also control runtime selection and startup; onboard saves open a confirmation.
Saving and device application are reported separately, with DPI/rate readback for
application. Stale proposals cannot overwrite newer settings, and concurrent
unsaved edits remain visible with a conflict notice.

Pi has no shell, arbitrary file-operation, auto-loaded extension, or firmware-flash
tools. Mouse control itself stays local. If you choose a cloud model, chat and the
settings read by its tools are sent to that provider.

## Macros and onboard settings

Create macros in the Macro tab, add key/mouse press and release steps or waits,
and assign them to profile buttons. Examples of keys include `space`, `X`, `ctrl`,
`ctrl+c`, `ctrl+shift+tab`, `volumeup`, and `playpause`. Validation checks key names,
paired releases, and macro references. Cancellation releases the macro's outputs;
shared modifiers are reference-counted. Changing profiles or stopping control
cancels running macros and releases their keys.

Timing follows the Windows scheduler, not a real-time guarantee. Input uses
`SendInput`; games that reject synthetic input or run at higher privileges may
behave differently from G HUB's virtual driver. Game-specific behavior needs testing.

Onboard saving targets **slot 1**. Before writing, all 16 user-memory sectors are
backed up. Unchanged bytes are preserved, CRCs recomputed, and every byte read back
for comparison. An unchanged profile skips writing. Profiles containing macros
are rejected because onboard macro writing is not implemented.

Onboard saving uses the edited profile. If local control is enabled, the active
app profile is reapplied afterward. Disabling control or stopping the service
returns to onboard slot 1. Restore also targets slot 1 and validates model, format,
and CRC, with another backup before restoring.

## G HUB migration and local data

The importer opens G HUB's SQLite database read-only and uses SQLite's backup API
for a consistent copy. It imports G703 HERO DPI, rate, basic presets, and explicit
simple sequence macros. Unsupported assignments produce warnings. G-Shift, Lua,
complex macros, and LIGHTSYNC editing are not fully compatible. The original
database is not modified; private settings are excluded from the repository.

Under the checkout or installation directory:

- `local/config.json`: mouse configuration.
- `local/pi-ui.json`: selected provider/model.
- `local/firmware/`: validated cached packages and update journal.
- `backups/`: onboard and migration backups.

Keep these directories when moving an installation. Normal mouse control performs
no network requests. Setup downloads dependencies; optional firmware checks access
Logitech's official distribution service; optional Pi requests use your chosen provider.

## Firmware updates — experimental

The firmware page compares the mouse version with an official G703 HERO candidate.
It fetches the public `ghub13 / Windows / public` catalog on request, validates the
G703-specific depot, SHA-256 hashes, target USB IDs, and signed image format, then
caches the package for offline use. You can also select a matching downloaded
`.depot`. G HUB is not required, and vendor firmware is not bundled or relicensed.

New versions in the supported channel/format can be discovered without changing
constants. A vendor layout/channel change requires an implementation update.
A failed check does not claim that the installed firmware is current.

On **2026-09-13**, both the official candidate and the test mouse were **22.02.15**.
**No real DFU transition, firmware transfer, or post-flash reboot was performed.**
The updater implements newer-version and wired-connection guards, settings backup,
signed DFU entry, boot-side identity matching, 16-byte transfer, journaling, and
post-reboot verification. Actual G703 flashing and interruption recovery remain
unverified; this is not a fully validated updater.

Same-version rewrites, downgrades, automatic retransmission, and bootloader recovery
are not provided. An incomplete journal blocks another update. Rechecking reads
identity/version only: it can reconcile a device already running the target
version or close a failure known to precede transfer. It does not resume a partial
write or restore firmware from a settings backup.

See [Firmware investigation](docs/FIRMWARE.md) for evidence and remaining hardware
verification requirements.

## Development and verification

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
cd desktop
npm test
npm run test:renderer
# Requires the local service/device; close the settings GUI first:
npm run test:lifecycle
```

Python has 59 tests and Pi/proposal integration has 9 tests. Renderer fixtures
cover editing, conflicts, save/application feedback, and firmware state. Real
GUI close/reopen tests verified continued local control at 1100 DPI and the absence
of Electron/Pi processes after closing. The Python service and virtualenv launcher
used approximately 40 MB working set in that observation.

Hardware checks covered receiver `046d:c539`, wired `046d:c090`, feature/status
reads, live mappings, host/onboard modes, slot-1 byte/CRC readback, and returning
to onboard control. Other models and the non-HERO G703 are unverified. Physical
button behavior, game macros, reconnect/sleep, and long-term use need further
validation. Synthetic firmware tests do not establish real flashing safety.

For the legacy Tkinter UI, run `.\.venv\Scripts\pythonw.exe launch.py` from the
checkout. [Desktop architecture](docs/DESKTOP.md) and [protocol notes](docs/PROTOCOL.md)
provide implementation details and test scope.
