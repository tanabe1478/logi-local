# Logi Local

[English](README.md) | **日本語**

[ドキュメント一覧](docs/README.ja.md)

G703 LIGHTSPEED **HERO / USB レシーバー・有線接続**向けの、Windows 用ローカル設定アプリです。
G HUB の実行ファイル・サービス・SDK は使いません。更新候補の確認には公式公開カタログへアクセスします。
実機の HID++ 4.2 通信とオンボード形式4を調べて実装しています。

## 対応デバイス

**現在の対応対象はG703 LIGHTSPEED HEROのみです。無印G703を含む、その他のデバイスには対応していません。**

別のデバイスへの対応追加には、プルリクエスト（PR）が必要です。
機種名・USB ID、対応する実装変更、対象デバイスでの実機検証結果を添えて提出してください。
機種名が似ていることや、HID++に対応していることだけでは互換性を判断できません。

## 起動

### React + Electron 版（Pi サイドバー付き）

普段使い用のユーザー別インストールは `Install-LogiLocal.ps1` を実行します。
実行前に、既存のLogi Localを通知領域から終了してください。
`%LOCALAPPDATA%\Programs\LogiLocal` に配置し、デスクトップとスタートメニューに
ショートカットを作成します。ログイン時はマウス制御だけが自動起動します。
初回は設定・バックアップを引き継ぎ、再インストール時はインストール先の設定を保持します。
既存のPythonを利用するユーザー別インストールで、管理者権限は不要です。

Windows・Python 3.13・Node.js 22.19以上を用意し、`Setup-Desktop.ps1` を実行します。
その後 `Start-LogiLocal.vbs` をダブルクリックすると新しい画面が開きます。
既存の `LogiLocal.exe` は旧Tkinter版です。新画面にはVBSランチャーを使ってください。
両方を同時起動すると競合を避けるため制御プロセスの起動を拒否します。

- 中央: DPI・レート・6ボタン・アプリ別プロファイル・マクロ・本体保存・更新画面。
- 右側: Piのチャット。プロバイダーとモデルを選択でき、回答を逐次表示します。
- Piは既存の `~/.pi/agent/auth.json` と `models.json` を利用します。
  `PI_CODING_AGENT_DIR` による変更にも対応します。認証情報はReact画面に渡しません。
- 初回認証が必要なら、Piでログインした後、サイドバーの「再読込」を押してください。
  ローカルモデルはPiの `models.json` に登録すると候補に表示されます。
- Piへの相談は変更案まで、チャットで「変更して」「反映して」と指示すると保存・適用まで進めます。
  DPI・レート・ボタン・アプリ別プロファイル・マクロを項目単位で変更できます。
  常駐の有効化・固定プロファイル・自動起動も操作でき、本体保存は確認画面を開きます。
  設定の保存と本体への適用を区別し、適用時はDPI・レートを読み戻して確認します。
  提案後に設定が変わっていた場合は上書きを拒否します。未保存の編集は保持し、競合を表示します。
- Piは設定用の専用ツールだけを使います。シェル、任意ファイル操作、
  拡張機能の自動読み込み、ファームウェア更新の開始はPiには許可していません。
- ウィンドウを閉じるとElectron・Piは終了し、マウス制御用のPythonだけが常駐します。
  マクロ・アプリ別切り替えは継続します。通知領域の「設定を開く」で画面を再起動できます。
  「マウス制御を終了」で常駐も終了します。未保存の設定は閉じる前に確認し、チャット表示は再起動時にリセットされます。
  自動起動も制御プロセスのみです。旧版からの移行時は一度、旧版を通知領域から終了してください。

マウス制御はローカルで動きます。クラウドモデルを選ぶと会話とツールで読んだ設定がその提供元に送信されます。
モデル選択は `local/pi-ui.json` に保存します。会話はメモリ内のみで、完全終了すると消えます。
変更済みのマウス設定は従来と同じ `local/config.json` に保存します。
Piが取得するモデル一覧はローカルのカタログです。「再読込」は認証・モデル設定を読み直します。

```powershell
cd desktop
npm run build
npm start
npm test
```

開発構成・テスト範囲は [デスクトップとPi](docs/DESKTOP.ja.md) を参照してください。

### 従来の Tkinter 版

このリポジトリはソースコードを公開しています。ビルド済み EXE は含みません。
Windows と Python 3.13 を用意し、`setup.ps1` を一度実行後、`Start-LogiLocal.vbs` をダブルクリックします。
Electron版をセットアップ済みなら、旧画面は `.venv\Scripts\pythonw.exe launch.py` で開けます。
`build.ps1` で `LogiLocal.exe` を生成すると、Python を別途インストールせずに実行できる形式になります。
通常のマウス制御はネットワーク通信を行いません。セットアップ／ビルド時の依存取得と、
ユーザーが純正の更新候補を確認・取得したときに Logitech 公式配布元への通信が発生します。

設定は隣の `local/config.json`、本体と G HUB のバックアップは `backups/` に保存します。
アプリを移動するときはこれらのフォルダも一緒に移動してください。

## 普段の操作

1. G HUB を終了します。GUI の「本体と設定 → G HUB を終了」でも終了できます。
2. 「ローカル制御」をオンにします。
3. プロファイルを選び、DPI・ボタンの動作・ショートカットを編集し「保存して反映」を押します。
4. アプリ別の設定はプロファイルを追加し、対象アプリに `.exe` の名前やパスを入力します。対象が空欄のプロファイルが既定です。
5. Electron版の × ボタンはGUIとPiを終了します。マウス制御は通知領域で継続し、「マウス制御を終了」で停止します。旧Tkinter版は画面を隠します。

「この設定に固定」でアプリ切り替えに関係なく同じ設定を使えます。
「自動切り替え」で前面アプリに追従します。アプリ名はフルパス、または `game.exe` のような名前を指定できます。
Electron版では複数の対象をカンマで区切ります。同じ対象が複数にあると先に登録したプロファイルが優先されます。

「保存して反映」はローカル制御を有効にし、適用中のプロファイルのDPI・レートを本体から確認します。
別のプロファイルが適用中なら、その名前とDPIを表示します。

Windows 起動時の自動起動は設定画面から選べます。G HUB の自動起動が残っている場合は、Windows の
「設定 → アプリ → スタートアップ」で G HUB をオフにしてください。
このアプリの有効化時に G HUB の競合プロセスが見つかると、理由を表示して有効化しません。

## 機能

| 機能 | ローカル制御中 | 常駐なし |
|---|---|---|
| DPI、DPI段階切り替え | 対応 | 本体保存で対応 |
| 125 / 250 / 500 / 1000 Hz | 対応 | 本体保存で対応 |
| 6ボタンのマウス／キー割り当て | 対応 | 本体保存で対応 |
| 修飾キー、ショートカット | 対応 | 修飾キー＋通常キー1個に対応 |
| 前面アプリ別の自動切り替え | 対応 | 非対応 |
| マクロ（1回／押している間／トグル） | 対応 | この実装では非対応 |
| バッテリー・充電表示 | 電圧から推定 | 表示用アプリが必要 |

通常のクリックはマウス本体から直接送信します。キーやマクロを割り当てたボタンだけを、
HID++ 0x8110 経由で本アプリが扱います。システム全体のキーボードフックやマウスフックは使いません。
G703 以外の入力デバイスを横取りしません。

## マクロ

「マクロ」タブで新規作成し、キー押下・キー解放・マウス押下・マウス解放・待機時間を追加します。
選択行の更新・削除・並べ替えにも対応します。その後「プロファイルとボタン」で割り当てます。

キー例: `space`, `X`, `ctrl`, `ctrl+c`, `ctrl+shift+tab`, `volumeup`, `playpause`。
キーやマウスの押下と解放は対で指定します。保存時に不正なキー、解放忘れ、存在しないマクロを検証します。
マクロを停止すると、そのマクロが押したキーを解放します。別のマクロと共有している修飾キーは参照数を管理します。
プロファイル変更・無効化・正常終了時にも、実行中のマクロを中断してキーを解放します。

待機は Windows のスケジューラによるため、厳密なリアルタイム保証はありません。
入力送信は Windows の `SendInput` を使います。ゲームが合成入力を拒否する場合や対象アプリの権限が高い場合、
G HUB の仮想ドライバーと同じ受付結果になるとは限りません。ゲーム内での確認が必要です。

## 本体に保存

「本体保存と設定 → 選択中の設定を本体に保存」で**スロット1**に保存します。
書き込み前に全ユーザーメモリ16セクターをバックアップし、変更のないバイトを保持し、CRCを再計算し、
書き込み後に全バイトを読み戻して一致を確認します。変更がなければ書き込みを省略します。
マクロを含むプロファイルの本体保存は、対応していない旨を表示して中止します。

本体保存は、編集中のプロファイルを保存します。常駐制御が有効なら、その後は前面アプリの設定が再適用されます。
「ローカル制御をオフ」または完全終了で本体スロット1へ戻します。
復元もスロット1のみが対象で、機種・形式・CRCを検証し、復元前にもバックアップを取得します。

## G HUB からの移行

「G HUB の設定を取り込む」は SQLite DB を読み取り専用で開き、SQLite backup APIで整合したコピーを取得します。
G703 HERO の DPI、ポーリングレート、基本プリセット、明示的な単純シーケンスマクロを取り込みます。
未対応の割り当ては警告を出します。G-Shift、Lua、複合マクロ、LIGHTSYNC編集など G HUB 全機能の互換実装ではありません。
既存設定2件と1マクロで取り込みを検証しました。元のDBは変更しません。個人設定はリポジトリに含みません。

## 検証

2026-09-11、Windows の実機 G703 LIGHTSPEED Wireless Gaming Mouse w/ HERO、レシーバー VID:PID `046d:c539`:

- G HUB のユーザープロセスを終了した状態で、名前・機能一覧・DPI・レート・電池電圧を読めることを確認。
- ボタンのライブマッピング変更と読み戻し、ホスト／オンボードのモード切り替えを確認。
- 本体スロット1へデスクトップ設定を保存し、CRCと全バイトの一致、および1600 DPIを確認。
- ローカル制御の開始と終了、本体モードへ戻る処理を確認。
- GUI全タブの起動と初期ウィンドウ内に収まることを確認。
- 自動テスト16件: CRC、255/256バイト読み取り、未知バイト保持、応答識別、設定検証、アプリパス照合、
  マクロ出力順・中断・重複キー所有者・ボタン解放など。

サイドボタンの物理操作、ゲーム内マクロ、抜き差し・スリープ復帰・再起動後の長時間使用は、
ユーザー環境での追加確認が必要です。他のLogicool機種、無印G703の動作は未検証です。
2026-09-13には有線 `046d:c090` で本体識別・ファームウェア情報の読み取りも確認しました。

## ファームウェア更新（実験的）

「ファームウェア」タブで本体の版と対応済みの純正候補を比較できます。
「純正ファイルを取得」で公式配布元から取得し、SHA-256・対象イメージを検証して
`local/firmware/` に保存します。取得後はオフラインで使えます。取得済みの `.depot` の選択も可能です。
G HUB のインストールや起動は不要です。純正ファームウェア自体は OSS 化せず、リポジトリにも同梱しません。

「公式の更新候補を確認」で Logitech の公開カタログ（ghub13 / Windows / public）を取得します。
G703 HERO専用depot・SHA-256・USB機種ID・署名付き形式を照合して、候補を保存します。
同じ公開チャネル・イメージ形式の新しい版はコード変更なしで検出できます。
配布形式やチャネルが変わった場合は対応が必要です。取得失敗を「最新版」とは表示しません。
2026-09-13に公式カタログから確認した候補は **G703 HERO 22.02.15** です。
実機の本体は **22.02.15** だったため更新不要と判定し、**DFU移行・書き込み・再起動は実施していません**。

本体が候補より古い場合のみ、有線接続と検証済みファイルを条件に、確認画面から更新を開始できます。
設定バックアップ、署名付きDFU移行、ブート側の本体ID照合、16バイト転送、再起動後の版確認を実装しています。
本体IDをブート側で確認できない場合は転送前に停止します。この制約を実機が満たすかも未検証です。
転送・再起動・障害時の復旧は **G703 実機では未検証** であり、動作保証のある完成済みアップデーターではありません。
通常の同版上書き・ダウングレード・自動再送・自動復旧は提供していません。
中断時は `local/firmware/update-journal.json` に状態を残します。未完了記録がある場合は再更新を拒否します。
「更新結果を再確認」は同一本体のバージョンを読むだけです。更新先の版で起動していれば完了と照合でき、
転送開始前の失敗で元の版が動作していればその失敗記録を終結できます。途中の転送を再送する機能ではありません。
ブートローダー状態からの復旧と、設定バックアップからのファームウェア復元は提供していません。

Pythonテスト59件とPi連携テスト9件を実施しています。公式カタログ取得・破損パッケージ・対象違い・
同版拒否・転送順序・エラー・本体ID不一致・再確認・Piからの保存と適用を検証しています。
**ファームウェアの実機書き込み検証は未完了です。** この条件を省略して完成とは扱いません。
詳細と根拠: [ファームウェア調査](docs/FIRMWARE.ja.md)。
