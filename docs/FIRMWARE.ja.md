# G703 HEROのファームウェア調査

[English](FIRMWARE.md) | **日本語** · [ドキュメント一覧](README.ja.md)

2026-09-13時点。この実装は実験的です。実際のファームウェア書き込みは行っていません。
接続した本体と確認した公式イメージがどちらも22.02.15だったため、DFU移行や同版の再書き込みを省略しました。

## 確認した根拠

- 有線の通常動作USB VID:PIDは `046d:c090`。HID++ longコレクションはff00/2、index ff。
- 機能0003から得たモデルIDは `4086 c090 0000`。
- アプリケーションはentity 1、`MPM 22.02.B0015`。ブートは `BL1 05.02.B0015`。
- 署名付きDFU制御機能00c2を読み取れ、availability bitはクリアでした。
- インストール済みG HUBの公式メタデータは、有線C090とブートAAF6を指定し、USB接続を要求して
  `g703_hero_v22_02_15.dfu` を参照していました。
- 同じdepotをG HUBを実行せず公式URLから取得でき、パッケージ全体のハッシュはメタデータと、
  内部イメージのハッシュは `dfu.json` と一致しました。

[確認した公式パッケージ](https://updates.ghub.logitechg.com/depots/58c73bea-abb7-4081-bf3a-9f4fd831ad09/g703_hero_dfu.depot)

パッケージSHA-256: `e6ba148ca26a38232dc9570da053fe3df13453fdac9b7db864dc63c79ebc5b82`

イメージSHA-256: `16acefe9a081632d5f9a1dc69fa777eb145ea31bf085091e5ae8ca7668fc8d05`

depotは86404バイトで、先頭の `10 01 17 20`、リトルエンディアンのJSON長、JSONファイル表、
各ファイルのリトルエンディアンの長さと内容が続きます。メモリ内で解析し、配布元が指定したパスへ展開しません。
イメージは78688バイトで、entity 1、署名形式1、`MPM22_D0` から始まります。
ハッシュは観測した公式データとの一致確認であり、このアプリが暗号署名を独立検証したことを意味しません。
署名の受理は本体の署名付きDFU処理に委ねます。

## 転送処理と制約

通信手順は [fwupdのHID++実装](https://github.com/fwupd/fwupd/blob/main/plugins/logitech-hidpp/fu-logitech-hidpp-device.c)
を参考にしています。これはプロトコルの根拠であり、G703での互換性の実証ではありません。

1. パッケージ、通常動作時の本体ID、新版であること、有線接続、DFU利用可否を再検証します。
2. オンボード設定をバックアップし、ローカルの更新記録を作成します。
3. 00c2のfunction 1、パラメーター `01 00 00 00 44 46 55` で署名付きDFUに移行します。
4. 一意なAAF6 long HIDコレクションを開き、0003のunit IDが同一本体と一致することを要求します。
5. 00d0を使い、イメージ全体を16バイトずつ転送します。functionは4, 1, 2, 3, 0, 1, 2, 3, 0, …の順で、
   毎回の応答と必要なbusy完了通知を待ちます。
6. entity 1を指定して00d0のfunction 5を送り、通常動作側へ再接続して本体IDとバージョンを確認します。

ブートデバイスの列挙、ブート側unit IDの取得可否、非同期カウンターの意味、実転送、復旧はG703で未検証です。
前提を満たせない場合は、本人性確認を緩めず停止します。自動再試行や復旧用の書き込みは実装していません。
更新記録は診断用です。GUIは実更新前に警告し、本体が候補と同じ版か新しい版なら更新を拒否します。
DFU中はWindowsの自動スリープを抑止しますが、強制終了やケーブル取り外しは防げません。

## 公式カタログの取得

その後、G HUBの起動や認証なしで取得できる
[公開カタログ](https://updates.ghub.logitechg.com/pipeline/v2/update/ghub13/win/public/details.json)
を確認しました。build 824196、version 2026.5.939708で、同じG703 HERO depotとハッシュでした。
[概要ファイル](https://updates.ghub.logitechg.com/pipeline/v2/update/ghub13/win/public/update.json)も公開されています。

アプリは要求時にこの公開チャネルを取得し、`g703_hero_dfu` だけを選びます。
取得元・パス・サイズ・ハッシュに加え、`dfu.json` の機種ID、manifestのイメージ対応、
イメージのハッシュ、署名形式ヘッダーを検証します。同じ形式の新版は定数の更新なしで検出できます。
配布チャネルや形式の変更にはコード側の対応が必要です。カタログの取得元はHTTPSで認証しますが、
別途記載された署名フィールドは独立検証していません。本体ファームウェアの署名検証はDFU側が行います。

パッケージは内容のハッシュに基づいた名前でキャッシュし、検証完了後にだけ候補メタデータを公開します。
更新候補の取得に失敗すると、前の候補を保持してエラーを返し、「最新確認済み」とは扱いません。
ベンダーのファームウェア・実行ファイル、本体固有ID、ユーザー設定はリポジトリに含みません。

## 完了条件と残る実機検証

- 実装・テスト済み: 公式候補の検出、ダウンロード検証、オフラインキャッシュ、機種・版の制約、
  転送の状態遷移、エラー処理、更新記録、再起動後の確認、不要な更新の拒否、読み取りだけの記録照合。
- 実機で観測済み: 有線の通常動作状態での本体ID、バージョン、DFU利用可否の読み取り。
  本体は公式候補と同じ22.02.15です。
- **未観測**: AAF6への移行、ブート側unit IDの挙動、署名付きイメージの実転送、
  旧版から新版へ更新後の起動、書き込み中断からの復旧。

予定する更新テストには、旧版の別のG703 HEROが必要です。模擬テストを実機の書き込み・復旧互換性の証拠とせず、
この条件が残ったまま、実機検証済みの完成したアップデーターとは扱いません。

「更新結果を再確認」はDFU移行やイメージ送信を行いません。同一本体が更新先の版で起動している場合、
または転送前の失敗後に元の版で起動している場合に記録を照合できます。
転送途中の失敗記録は保持し、ブートローダーからの復旧や再書き込みは提供しません。
