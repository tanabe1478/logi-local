# G703 HEROのリバースエンジニアリング記録

[English](PROTOCOL.md) | **日本語** · [ドキュメント一覧](README.ja.md)

2026-09-11の観測記録です。ファームウェアの改変や専有バイナリの再配布は行っていません。
ローカルのG HUB設定DBをSQLiteの読み取り専用モードで開き、既存設定をバックアップして変換しました。
公開されているHID++実装をフレームとフィールド位置の参考にしています。
Solaar由来のプロファイル処理と電池データは [第三者の権利表記](../THIRD_PARTY_NOTICES.md) に記載しており、
クリーンルーム実装とは主張しません。

## デバイスと通信

- VID 046D、レシーバーPID C539、interface 2、usage page FF00、usage 2。
- WindowsはshortとlongのHID++コレクションを別々に公開します。hidapiでlong側を開きます。
- longレポートは `[11, device=01, feature_index, (function<<4)|software_id, 16バイトに埋めたparameters]`。
- pingはprotocol 4.2、marker 5Aを返しました。本体名はG703 LIGHTSPEED Wireless Gaming Mouse w/ HEROです。
- feature indexはIRootで動的に解決します。応答はdevice・feature・function/software IDで照合し、
  非同期通知を別に振り分けます。
- 観測したfeature IDは0001, 0003, 0005, 1D4B, 0020, 1001, 8071, 8100, 8110, 8060, 2201, 00C2などです。
  通常のマウス制御はメーカー内部機能を使いません。その後の実験的な更新処理は
  [ファームウェア調査](FIRMWARE.ja.md) に記載しています。

## 確認した操作

| Feature | Function | 内容 |
|---|---|---|
| 2201 | 1 / 2 / 3 | DPI一覧 / 現在値 / 設定 |
| 8060 | 0 / 1 / 2 | 対応する間隔 / ポーリング間隔取得 / 設定 |
| 1001 | 0 | ビッグエンディアンのmVと充電フラグ |
| 8110 | 0 | 物理ボタン6個 |
| 8110 | 1 / 2 | ボタン通知開始 / 停止 |
| 8110 | 3 / 4 | 6バイトのライブ割り当て取得 / 設定 |
| 8100 | 0 | オンボード形式の記述子 |
| 8100 | 1 / 2 | モード設定 / 取得（1: 本体、2: ホスト） |
| 8100 | 3 / 4 | 使用セクター設定 / 取得 |
| 8100 | 5 | 16バイト読み取り。sectorとoffsetはビッグエンディアン |
| 8100 | 6 / 7 / 8 | 書き込み開始 / データ送信 / 完了 |
| 8100 | B / C | DPI段階の取得 / 設定 |

G HUBのデスクトップ設定が有効なとき、8110の割り当ては `01 02 03 00 00 00` でした。
`01 02 03 04 05 00` の書き込みが受理され、読み戻しも一致しました。
各値は物理ボタンに対応する本来のマウスボタン番号で、0はホストモードの通常HID出力を抑制します。
通常の割り当てはクリックやドラッグを維持し、キー・マクロ・DPI操作だけをソフトウェアで処理します。
イベントはビッグエンディアンの押下ボタンビットマスクです。
物理操作の通知とゲーム側の受付は、利用環境で追加確認が必要です。

## オンボードメモリ

記述子: `01 04 01 05 01 06 10 00 ff 0a 04 ...`

- memory model 1、profile format 4、macro format 1。
- プロファイル5枠、ボタン6個、ユーザーセクター16個、**1セクター255バイト**。
- CRC16/CCITT-FALSE。初期値FFFF、多項式1021、末尾2バイトにビッグエンディアンで保存。
- ディレクトリー項目は4バイト: ビッグエンディアンのsector、有効フラグ、予約バイト。FFFFで終了。
- 初期状態ではセクター1〜5を参照し、slot 1だけが有効。ディレクトリーCRCは4037、元のprofile 1は2CAC。

最後の読み取りはoffset 239から始め、最初の240バイトの後に、その読み取りの末尾15バイトだけを追加します。
offset 240から読む、または16バイトすべてを追加すると重複・超過します。実機のCRCを使って原因を確認し修正しました。

| Offset | 使用する内容 |
|---|---|
| 0 | レポート間隔（ms） |
| 1 / 2 | 既定DPI index / shift DPI index |
| 3–12 | リトルエンディアンのDPI値5個 |
| 32 | 4バイトの主ボタン割り当て6個。他のbank領域は保持 |
| 160–207 | UTF-16LEのプロファイル名。保持する |
| 253–254 | この255バイトセクターのCRC |

ボタンのエンコードは、マウス `80 01 mask16be`、キー `80 02 modifiers usage`、
無効 `80 00 ff ff`、DPI切り替え `90 05 ff 00` です。
省電力、別ボタン、照明など、他のバイトは保持します。

デスクトップ設定をslot 1へ書き込み、全バイトの読み戻しが一致しました。
元のスナップショットは復元用としてローカルに保持し、公開していません。
アプリ切り替えではフラッシュメモリへ書き込みません。

## ローカル制御

HIDを所有する単一スレッドがコマンドと通知を処理し、前面アプリを200 msごと、
電池・状態を30秒ごとに確認します。マクロは別スレッドでWindows SendInputを使い、可能ならスキャンコードを指定します。
出力の所有者を参照数で管理し、中断要求で待機を終了して、そのマクロが所有する入力を解放します。

通常のマウス制御はグローバルキーボードフック、仮想ドライバーの導入、シェル実行マクロ、
テレメトリー、クラウドログインを使いません。常駐サービスとの接続は認証付きローカル名前付きパイプです。
任意のPi利用と公式カタログへの通信は [デスクトップとPi](DESKTOP.ja.md) を参照してください。

旧Tkinter版はGUIとエンジンを同一プロセスで動かします。Electron版は独立したPythonサービスへ接続し、
GUIを閉じても制御を続けます。サービスの正常終了ではマクロを止め、本来の割り当てと本体slot 1へ戻します。
抜線などのエラーは間隔を空けて再接続します。強制終了やファームウェア固有のスリープ挙動には制約があり、
障害時には制御を再度有効にするか、本体の電源を入れ直してください。
