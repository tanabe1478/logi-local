# デスクトップとPiの連携

[English](DESKTOP.md) | **日本語** · [ドキュメント一覧](README.ja.md)

React画面は設定エディターと右側のチャット欄を提供します。Electronはダイアログと、
画面を開いている間だけ必要なプロセスを管理します。

- Pythonの `-m logilocal.service` が、マウス制御エンジンとトレイを所有します。
  GUI終了後も独立して動作します。GUI側の一時的なPython中継プロセスは、
  Windowsの名前付きパイプで接続します。認証には
  `%LOCALAPPDATA%/LogiLocal/pipe.key` のユーザー別ランダムキーを使います。
  サイズを制限したJSONバイト列だけを受け付け、pickleは読み込みません。
  TCP/HTTPポートは開きません。リクエストIDは接続ごとに分離し、古いGUIへの応答が
  再接続後のリクエストに混ざらないようにしています。
- `electron/pi-worker.mjs` は固定バージョンのPi SDKをElectronのNodeランタイムで実行します。
  モデル名、応答テキスト、設定変更案などをGUIへ返します。

React画面では `contextIsolation`、サンドボックス、限定したpreload IPCを有効にしています。
Nodeへの直接アクセス、画面遷移、ポップアップ、ネットワーク接続は禁止しています。
モデルへの外部リクエストはPiプロセスが行い、Electron側でIPCの送信元と操作名を確認します。

## 設定操作

Piは `ModelRuntime` を通じて既存の認証とモデル設定を利用します。拡張機能、コンテキストファイルの探索、
スキル、プロンプトテンプレート、組み込みのコーディング用ツールは無効です。
専用ツールは設定の読み取り、プロファイル・ボタン・マクロの編集、提案の適用、
常駐制御、起動設定、本体保存の確認、ファームウェアの読み取り確認を扱います。

提案JSONはPythonで検証します。適用時はHID所有スレッド上で変更元との一致を確認して保存し、
古い提案による上書きを防ぎます。明示的な変更指示ではPi自身が保存・適用でき、
相談だけなら提案までに留めます。本体への適用は保存とは別に扱い、DPI・レートを読み戻して確認します。
ファームウェアへの書き込みはPiのツールには含みません。

Piが保存した設定はGUIへ通知します。ユーザーに未保存の編集がある場合は保持し、
最新設定の読み直し、または上書きの競合を表示します。

## ファームウェアと終了処理

ファームウェア更新は実験的です。Electronで確認ダイアログを表示し、更新中の通常終了を防ぎます。
バックエンドは機種・バージョン・ハッシュを確認します。Electronが閉じたり異常終了した場合も、
独立したHID所有プロセスは進行中の処理を継続します。常駐側のトレイも転送中の終了を拒否します。
OSによる強制終了まで防ぐ保証ではありません。

## インストールと常駐

ソース版のランチャーは `desktop/node_modules/electron/dist/electron.exe` と `.venv` を使います。
`Install-LogiLocal.ps1` はこの構成を `%LOCALAPPDATA%/Programs/LogiLocal` に配置し、
ショートカットを作成して、初回の設定・バックアップを移行し、制御のみの自動起動を登録します。
既存のPythonを使う方式で、単体EXEインストーラーではありません。
再インストールではインストール先の設定を保持します。`LogiLocal.exe` は旧Tkinter版です。

設定画面を閉じるとElectron、Pi、中継プロセスは終了します。PythonのHID・トレイ処理は残り、
プロファイル選択、マクロ、アプリ別切り替えを継続します。トレイやランチャーから新しいGUIで再接続できます。
未保存の設定は閉じる前に確認します。チャット表示は開き直すとリセットされます。
トレイの「マウス制御を終了」で常駐も止まり、本体設定に戻ります。

ログイン時はpythonwで `launch-service.py --enable` だけを起動し、GUIやPiは起動しません。
既存の自動起動設定はGUIの初回初期化時に移行します。

## 検証

- Python 59件: 認証付き名前付きパイプの切断・再接続、応答の分離、終了処理、
  本体・ファームウェア処理、設定の比較保存、未対応操作の拒否。
- Node: 実際のPi SDKをループバック上の模擬モデルに接続し、ストリーミング、設定取得、
  項目単位の提案、保存、適用、会話リセットを検証。Pythonの実際の設定検証を使いますが、
  設定保存とハードウェアは模擬です。コーディング用ツールが公開されないことも確認します。
  このテストではクラウドモデルを呼びません。
- 提案のテスト: 明示的な適用前に書き込まないこと、不正設定の拒否、古い提案の拒否。
- Electron画面テスト: 実際のアプリのタブ、未保存マクロの編集、読み取り専用の更新状態、
  モデル一覧、右サイドバー配置。1450×920と1080×700の画像は無視対象の `research/` に保存します。
  ユーザー設定は保存しません。
- ローカルの既存Pi認証からモデル一覧を取得できることを確認。実装検証では課金される
  クラウドモデルへのプロンプトは送信していません。
- 分離したヘッドレスEdge画面テスト: Pi変更のエディター反映、未保存編集の保持、
  競合時の再読み込み、公式候補表示。起動中のユーザーアプリは操作しません。
- `npm run test:lifecycle`: 実際のGUIを2回開閉し、Piモデル一覧とGUI終了後の常駐状態、
  プロファイル、本体DPIを確認。G703の1100 DPIで検証しました。終了後はElectron・Piが残らず、
  Python制御と仮想環境ランチャーのワーキングセット合計は約40 MBでした。

`desktop` で `npm test` を実行すると分離したPi・提案テストが動きます。
`npm run test:ui` は開発環境と対象のG703 HERO 22.02.15が必要です。既存のLogi Localは終了してください。
Pythonテストはリポジトリ直下で `.venv\Scripts\python.exe -m unittest discover -s tests` を実行します。
